# QA-чекліст Airsoft Club

Середовище: **staging** (`airsoft-staging.tangle.care`, staging-бот, тестова група). Прод не чіпати.
Ролі: **Гравець**, **Капітан** (капітан команди), **Адмін** (`ADMIN_IDS`).
Потрібно щонайменше 3 Telegram-акаунти: адмін і два гравці.
Відомі баги з `docs/AUDIT-2026-10.md` позначені **[BUG #N]**: перевіряйте, що вони відтворюються до фіксу і зникли після.

Позначки: ☐ не перевірено · ✅ ок · ❌ баг (додати посилання на issue)

## 0. Середовище та ізоляція
- ☐ `https://airsoft-staging.tangle.care/api/health` → `"env":"staging"`
- ☐ `/start` у staging-бота → відповідь з `🧪 STAGING`, кнопка «Увійти» відкриває staging-домен
- ☐ Анонси йдуть у тестову групу (тема «Анонси»), а не в прод-канал
- ☐ DM гравцю, якого немає в `TEST_CHAT_IDS`, не надсилається (у логах `Blocked sendMessage`)
- ☐ `/.env`, `/package.json`, `/index.js` не віддають вміст файлів
- ☐ Після деплою нова версія видна без очищення кешу (заголовок `cache-control: no-cache` на `/`)

## 1. Вхід і реєстрація
- ☐ Новий користувач → `/start` → «Увійти» → автоматично створюється гравець
- ☐ Модалка позивного: тільки кирилиця, ≤24 символи, крок підтвердження
- ☐ Позивний, який уже має інший гравець, відхиляється
- ☐ Змінити позивний вдруге не можна
- ☐ Будь-який текст боту → кнопка «Увійти»
- ☐ Нема інтернету під час завантаження → екран «Спробувати знову» працює

## 2. Профіль
- ☐ Шапка: знак розрізнення відповідає рівню, LV, позивний, команда, кільце рейтингу
- ☐ Статистика (ігри, перемоги, %, MVP, смерті, виживання) збігається з даними
- ☐ Нагороди: тап показує опис; модалка «Новий бейдж» показується один раз
- ☐ Друзі: пошук, запит, прийняти/відхилити, список
- ☐ Історія ігор: перемога/поразка/нічия коректні

## 3. Список ігор
- ☐ Фільтри «Всі / Скоро / Live / Архів» фільтрують правильно
- ☐ Картка: дата, час, локація, ціна, тривалість, раунд, «Вільно N» / «Місць немає», смуга заповненості
- ☐ Лічильник LIVE у шапці
- ☐ Тап по картці відкриває деталі гри; посилання `startapp=game_<id>` відкриває ту саму гру

## 4. Деталі гри та запис
- ☐ Брифінг: дата, локація, ціна, мій чек, знижка з бонусу
- ☐ Запис: модалка спорядження, сума = база + доп., ліміти складу
- ☐ Повторний запис неможливий; гравець з чорного списку отримує відмову
- ☐ Повна гра → лист очікування + DM
- ☐ Запис на завершену/скасовану гру неможливий **[BUG #11]**
- ☐ Два гравці записуються на останнє місце одночасно → записується лише один **[BUG #11]**
- ☐ Скасування запису: підтвердження, перший з листа очікування переходить у гру + DM, анонс «вільні місця»
- ☐ Скасування до старту скасовує мою поїздку, пасажири отримують DM

## 5. Check-in і раунди
- ☐ Адмін «Відкрити Check-in» → анонс у групі
- ☐ Гравець «Check-in — я на місці» → без помилки **[BUG #1]**, статус «очікує»
- ☐ Повторне натискання не скидає підтвердженого гравця **[BUG #1]**
- ☐ Адмін підтверджує/відхиляє check-in, ручний check-in
- ☐ «Почати гру»: неявки → no-show, розподіл команд (TvT по командах, Random по рейтингу, FFA)
- ☐ Подвійне натискання «Почати»/«Завершити» не дублює раунд і бали **[BUG #3]**
- ☐ Гравець «Мене вбили» → у списку мертвих; адмін може відмінити
- ☐ Кінець раунду A / B / Нічия → анонс; FFA рахується правильно **[BUG #18]**
- ☐ Офлайн: вимкнути мережу під час завершення раунду → результат відправляється після відновлення
- ☐ Перемішати команди, перемістити гравця, кікнути (до та після check-in)
- ☐ Додати гравців за @username / t.me посиланням
- ☐ Редактор складу спорядження
- ☐ «Завершити гру» → рейтинг, бейджі, повідомлення про переможця

## 6. MVP
- ☐ Після раунду адмін обирає MVP тільки з команди-переможця
- ☐ Наступний раунд недоступний, доки не обрано MVP
- ☐ Гравець бачить «MVP обирає адмін»

## 7. Білінг (адмін)
- ☐ Доп. позиції гравцю, лише для підтверджених
- ☐ Сума відповідає ціні гри, а не 700/500 **[BUG #9]**
- ☐ Передоплата, «Оплачено» (подвійне натискання не дублює **[BUG #16]**), фільтр «тільки боржники»
- ☐ DM одному гравцю і «DM боржникам» (з гравцем, який заблокував бота, **[BUG #16]**)
- ☐ Експорт XLSX: публічний і організаторський
- ☐ Знижка з бонусу враховується тільки після підтвердження адміном **[BUG #6]**

## 8. Карпул
- ☐ Створити/редагувати поїздку (місця, локація, час, авто), DM пасажирам при зміні
- ☐ Запит місця (не у свою поїздку), DM водію
- ☐ Водій приймає/відхиляє, ліміт місць
- ☐ Водій кікає пасажира, видаляє поїздку → DM
- ☐ Повторний запит після відмови **[BUG #20]**; зменшення місць нижче зайнятих **[BUG #20]**

## 9. Команди
- ☐ Список команд, деталі команди
- ☐ Створити команду (попередження про вихід з поточної)
- ☐ Подати / скасувати заявку; капітан отримує DM з кнопками
- ☐ Кнопки «Прийняти / Відхилити» в DM працюють **[BUG #8]**
- ☐ Капітан: прийняти заявку в застосунку, запросити, кікнути, передати капітанство, розпустити (DM усім)
- ☐ Запрошення: прийняти/відхилити
- ☐ Вийти з команди; капітан, який вийшов, втрачає права **[BUG #17]**
- ☐ Посилання `startapp=team_<id>` відкриває команду **[BUG #22]**

## 10. Рейтинг
- ☐ Гравці: подіум топ-3, пагінація
- ☐ Команди, сезон («Немає активного сезону», коли сезону немає)

## 11. Колесо фортуни
- ☐ Кількість обертів (1 безкоштовний + 1 за кожні 50 рейтингу)
- ☐ Оберт, модалка виграшу
- ☐ Швидкі паралельні оберти не дають більше, ніж дозволено **[BUG #5]**
- ☐ Запит на використання: вибір гри для знижки, гра в статусі «Скоро» доступна **[BUG #10]**
- ☐ Адмін «Запити бонусів» → підтвердження

## 12. Опитування
- ☐ Пропозиція раз на день, «Пізніше» ховає до наступного дня
- ☐ Обов'язкові поля, відправка, після відправки більше не показується
- ☐ Адмін бачить відповіді

## 13. Штаб (адмін)
- ☐ Вкладка «Штаб» видна лише адмінам
- ☐ Створення гри (2 кроки) → анонс у групі з кнопкою «Записатися»
- ☐ Нарахувати / зняти бали
- ☐ Чорний список: додати / прибрати

## 14. Безпека (виконує розробник)
- ☐ Запит до API без `x-telegram-init-data` → 401
- ☐ Гравець викликає `/api/admin/*` → 403
- ☐ `POST /api/register` з чужим `team_id` не додає в команду **[BUG #7]**
- ☐ Старий initData (>24 год) відхиляється **[BUG #12]**
- ☐ Назва команди `<b>test` не ламає DM капітану **[BUG #14]**
- ☐ У проді `DEV_MODE` не вмикає обхід авторизації **[BUG #2]**

## 15. UI / редизайн
- ☐ Телефони: iPhone SE (375), iPhone 15 (390), великий Android (412+), Telegram Desktop
- ☐ Фон-камуфляж не заважає читати текст на жодному екрані
- ☐ Шрифти Oswald / IBM Plex / JetBrains Mono завантажуються, кирилиця без «квадратиків»
- ☐ Довгі позивні, назви команд і локації не ламають верстку (обрізаються)
- ☐ Нижня навігація не перекривається вирізом iPhone (safe area)
- ☐ Анімації переходів плавні, без мерехтіння; вимкнені при «Reduce motion»
- ☐ Модалки закриваються, не прокручують фон
- ☐ Порожні стани (немає ігор, команд, друзів) виглядають акуратно
